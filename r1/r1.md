# TheMealDB, Find Recipes by Ingredient

## What it is + why a designer might care
TheMealDB is a free, crowd-sourced database of recipes from around the world. You can
search meals by name, main ingredient, category, or cuisine, and get each recipe's
ingredients, instructions, and a photo. For designers, it's an easy way to build anything
food-related, like meal planners or "recipe book" tools, without having to collect those
recipe data ourselves.

## Setup
1. Install requests: `pip install requests`
2. No sign-up needed. The free test key is just `1`, and it goes **inside the URL path**:
   `https://www.themealdb.com/api/json/v1/1/...`
3. The test key is for development and learning. Releasing an app publicly needs a
   $10 lifetime supporter key.

## Working example
This finds meals that use an ingredient, then gets the full recipe for the first one.

```python
import requests

url = "https://www.themealdb.com/api/json/v1/1"    # the "1" is the free test key

# --- Part 1: search by ingredient ---
ingredient = "salmon"
r = requests.get(f"{url}/filter.php", params={"i": ingredient}, timeout=10)

if r.status_code != 200:
    print("Sorry, the search didn't work:", r.status_code, r.reason)
else:
    meals = r.json()["meals"]

    # No results come back as None or the text "no data found", not an empty list
    if meals is None or meals == "no data found":
        print(f"No meals found with {ingredient}.")
    else:
        print(f"{len(meals)} meals use {ingredient}:")
        for meal in meals[:3]:                       # just the first 3
            print("-", meal["strMeal"])

        # --- Part 2: get the full recipe for the first meal ---
        first_id = meals[0]["idMeal"]
        r2 = requests.get(f"{url}/lookup.php", params={"i": first_id}, timeout=10)
        recipe = r2.json()["meals"][0]

        print()
        print(recipe["strMeal"], "|", recipe.get("strArea"), recipe.get("strCategory"))

        # Ingredients aren't a list: they're separate keys strIngredient1, strIngredient2, ...
        for n in [1, 2, 3, 4, 5]:                    # the first 5 ingredients
            ing = recipe.get(f"strIngredient{n}")
            amount = recipe.get(f"strMeasure{n}")
            if ing:                                   # skip empty ones
                print("  ", amount, ing)
```

Output with `ingredient = "salmon"`:
```

- Baked salmon with fennel & tomatoes
- Fish Soup (Ukha)
- Honey Teriyaki Salmon

Baked salmon with fennel & tomatoes | British Seafood

```

Output with `ingredient = "zzzz"`:
```
No meals found with zzzz.
```


## Gotchas (ones I ran into)
1. **"No results" comes back as text.** Searching for "zzzz" gives
   `{"meals": "no data found"}` instead of an empty list. If my code looped over that,
   it would loop over letters and crash, so it checks for "no data found" first.
```python
if meals is None or meals == "no data found":
    print(f"No meals found with {ingredient}.")
else:
    for meal in meals[:3]:
        ...
```
2. **The search only gives a preview.** Searching by ingredient only gives each meal's
   name, photo, and ID. To get the ingredients, you have to ask again with the meal's ID
   (lookup.php).
3. **Ingredients are separate numbered keys, not a list.** Each recipe has
   strIngredient1 to strIngredient20, and the extra ones are empty when a recipe has
   fewer ingredients.
    ```python
    {
    "strMeal": "Baked salmon with fennel & tomatoes",
    "strIngredient1": "Fennel",
    "strIngredient2": "Parsley",
    "strIngredient3": "Lemon",
    ...
    "strIngredient20": "",
    }
    ```

## Design angle
**Project idea:** a meal-prep helper for college students. You type the protein you
already bought (like a big pack of salmon from Costco), and it suggests several recipes
to rotate through the week.

**Ethical / UX consideration:** There's no nutrition, calorie, or allergy data on the
recipes. So an app shouldn't present these as "healthy" or "safe" meals, and should 
tell users that allergens aren't checked.
